# Feature Specification: Game Boy Color エミュレーター（LispGB）

**Feature Branch**: `001-gbc-emulator`

**Created**: 2026-10-07

**Status**: Draft

**Input**: User description: "common lispでgameboy colorエミュレーターを開発してください。コマンドラインから起動できるもので良いです。/home/bubio/Develop/ruxboy と同等のものとします。"

## 概要

コマンドラインから起動する Game Boy / Game Boy Color エミュレーターを作る。
機能と品質の水準は既存のエミュレーター RuxBoy（`~/Develop/ruxboy`）と同等とする。
RuxBoy が備える機能は次のとおり：CPU・画面・音声のエミュレーション、主要な
カートリッジ方式（MBC1/2/3/5）、GBC 固有機能、バッテリーバックアップ RAM の
永続化、セーブステート、CLI オプション、設定ファイル、最近使った ROM の一覧、
ヘッドレス検証モード。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ROM を起動してゲームをプレイする (Priority: P1)

ユーザーはターミナルで ROM ファイル（`.gb` / `.gbc`）を指定して起動する。
ウィンドウにゲーム画面が表示され、音声が鳴り、キーボードで操作してプレイできる。
Esc キーかウィンドウを閉じる操作で終了する。

**Why this priority**: エミュレーターの存在意義そのもの。これがなければ他の機能に
価値がない。

**Independent Test**: テスト ROM（例: cgb-acid2）と、入力を受け付ける自作・フリーの
ROM を起動する。画面が正しく描画されること、キー入力が反映されること、音が出ることを
確認できれば単独で価値がある。

**Acceptance Scenarios**:

1. **Given** 有効な GBC ROM ファイルがある, **When** `lispgb game.gbc` を実行する, **Then** ウィンドウが開き、ゲーム画面が表示され、音声が再生される
2. **Given** ゲームが実行中である, **When** 矢印キー / Z / X / Enter / 右Shift を押す, **Then** それぞれ十字キー / B / A / Start / Select としてゲームに伝わる
3. **Given** ゲームが実行中である, **When** Esc を押すかウィンドウを閉じる, **Then** エミュレーターが正常終了する
4. **Given** モノクロ Game Boy（DMG）用の ROM がある, **When** それを起動する, **Then** DMG 互換の表示で正しく動作する

---

### User Story 2 - ゲームの進行を保存・再開する (Priority: P2)

バッテリーバックアップ付きのカートリッジでは、ゲーム内セーブが `.sav` ファイルとして
自動で保存される。次に起動したときは、その続きから遊べる。加えて、F1 キーで
任意の時点の状態（セーブステート）を保存でき、F3 キーで復元できる。

**Why this priority**: 長いゲームを遊ぶには必須。ただしプレイ自体（P1）が先にないと
成り立たない。

**Independent Test**: バッテリー付き ROM でゲーム内セーブし、終了・再起動して
データが残っていることを確認する。F1 で保存し、状態を変えてから F3 で元に戻ることを
確認する。

**Acceptance Scenarios**:

1. **Given** バッテリー付きカートリッジでゲーム内セーブした, **When** エミュレーターを終了して再起動する, **Then** セーブデータが引き継がれている
2. **Given** ゲームが実行中である, **When** F1 を押してから進行し、その後 F3 を押す, **Then** F1 を押した時点の状態に正確に戻る
3. **Given** 別の ROM 用のセーブステート、または壊れたセーブステートがある, **When** F3 で復元しようとする, **Then** 復元は拒否され、現在の実行状態は壊れず、ユーザーに通知される
4. **Given** ゲームがセーブ RAM を書き換えている, **When** 書き込みが落ち着いてから約1秒が経つ、または終了する, **Then** `.sav` が書き込まれる。書き込みは途中で中断しても既存ファイルが壊れない方法で行う

---

### User Story 3 - 表示と起動の挙動をカスタマイズする (Priority: P3)

ユーザーは CLI オプションで表示倍率、フルスクリーン、拡大時の補間方式を指定できる。
設定ファイルに既定値を書いておけば、毎回オプションを指定しなくて済む。
`--recent` を指定すると、最近使った ROM の一覧が表示される。

**Why this priority**: 快適さの向上。なくてもプレイはできる。

**Independent Test**: `--scale 2`、`--fullscreen`、`--shader smooth` の各オプションで
起動して表示を確認する。設定ファイルを書き換えて、既定値が変わることを確認する。
`--recent` の出力を確認する。

**Acceptance Scenarios**:

1. **Given** 初回起動である, **When** 起動する, **Then** OS の慣習に従った場所に既定値入りの設定ファイルが自動生成される
2. **Given** `--scale N` を指定した, **When** 起動する, **Then** 画面が N 倍で表示される（1〜8。9 以上は 8 に丸める。既定は 4）
3. **Given** `--fullscreen` を指定した, **When** 起動する, **Then** フルスクリーンで表示され、`--scale` は無視される
4. **Given** `--shader nearest|smooth` を指定した, **When** 起動する, **Then** 指定した補間方式で拡大表示される（既定は nearest）
5. **Given** 過去に ROM をいくつか起動した, **When** `--recent` を実行する, **Then** 最近使った ROM が新しい順に最大10件表示され、エミュレーターは終了する
6. **Given** 任意の状態である, **When** `-h/--help` または `-v/--version` を実行する, **Then** 使い方またはバージョンが表示されて終了する

---

### User Story 4 - 正確性を自動で検証する (Priority: P2)

開発者は、ウィンドウを出さないヘッドレスモード（`--headless --frames N --screenshot PATH`）
と、標準テスト ROM 群（Blargg、Mooneye acceptance、dmg-acid2 / cgb-acid2）を使って、
エミュレーションの正確性を自動検証できる。テスト ROM は、ライセンス上の理由で
リポジトリに含めず、スクリプトで取得する。

**Why this priority**: 「RuxBoy と同等」を客観的に示す唯一の手段であり、回帰を防ぐ。
P1 の開発と並行して必要になる。

**Independent Test**: テスト ROM を取得するスクリプトとテスト一式を実行し、
合否の一覧を得る。

**Acceptance Scenarios**:

1. **Given** テスト ROM を取得済みである, **When** テスト一式を実行する, **Then** 各テストの合否が一覧表示され、すべて合格ならテスト全体も成功として終了する
2. **Given** acid2 ROM がある, **When** `--headless --frames N --screenshot out.bmp` で実行する, **Then** ウィンドウを表示せずに N フレーム実行し、画面を画像ファイルとして保存して終了する。その画像は期待画像と一致する

---

### Edge Cases

- ROM ファイルが存在しない、読めない、サイズが小さすぎる → 分かりやすいエラーメッセージを出し、0 以外の終了コードで終了する
- 未対応のカートリッジ方式（MBC6/7、HuC 等）の ROM → 未対応である旨を表示して終了する
- ROM ヘッダのチェックサムが不正 → 警告は出すが、起動は継続する
- CLI オプションの値が不正（`--scale abc`、`--shader foo` など）や、値がない → エラーと使い方を表示し、0 以外の終了コードで終了する
- 設定ファイルが壊れている、または未知のキーがある → 解釈できる項目だけ採用し、残りは既定値にする。起動は継続する
- `.sav` のサイズがカートリッジの RAM サイズと一致しない → 読み込まずに警告を出す。既存ファイルは上書きせず退避する
- 設定ディレクトリが存在しない、または作成できない → 自動で作成を試みる。失敗した場合は設定を保存せずに起動を継続する
- 音声デバイスが利用できない → 無音で動作を継続する（タイミングは別の手段で維持する）
- MBC3 のリアルタイムクロック → セッション中は実時間で進む。終了中の経過時間の永続化は RuxBoy と同様に対象外とする

## Requirements *(mandatory)*

### Functional Requirements

**エミュレーションコア**

- **FR-001**: システムは Game Boy Color の CPU（SM83 相当）の全命令を、サイクル単位のタイミングを含めて実行できなければならない
- **FR-002**: システムは割り込み（VBlank / STAT / Timer / Serial / Joypad）、タイマー（DIV / TIMA）、HALT / STOP を正しくエミュレートしなければならない
- **FR-003**: システムは画面（BG / Window / スプライト、スキャンライン単位の描画、STAT モード遷移、LYC 一致）を 160×144 で描画しなければならない
- **FR-004**: システムは音声4チャンネル（矩形波2、波形メモリ、ノイズ）とフレームシーケンサーをエミュレートし、ステレオで出力しなければならない
- **FR-005**: システムは ROM のみ、MBC1、MBC2、MBC3（RTC 含む）、MBC5 のカートリッジに対応しなければならない
- **FR-006**: システムは GBC 固有機能（倍速モード、VRAM / WRAM バンク切替、カラーパレット、BG 属性、HDMA / GDMA、OAM DMA）をエミュレートし、DMG 専用 ROM は DMG 互換モードで動かさなければならない
- **FR-007**: システムはジョイパッドレジスタ（グループ選択、押下状態、割り込み発生）をエミュレートしなければならない
- **FR-008**: システムはシリアル出力を内部に記録できなければならない（テスト ROM の結果判定に使う）
- **FR-009**: システムは実機と同じ速度（約 59.7 フレーム/秒）で動作し、音声の再生速度でペースを保たなければならない

**永続化**

- **FR-010**: システムは、バッテリー付きカートリッジの外部 RAM を、ROM と同じ場所の `<ROM名>.sav` へ読み書きしなければならない。書き込みは、最後の変更から約1秒経ったときと終了時に、途中で中断しても既存ファイルが壊れない方法で行う
- **FR-011**: システムは、CPU・メモリ・画面・音声・カートリッジ・ジョイパッドの全状態を含むセーブステートを保存・復元できなければならない（F1 で保存、F3 で復元、スロットは1つ）
- **FR-012**: セーブステートは、識別子・フォーマットバージョン・ROM 識別情報を持たなければならない。不一致や不正なデータを復元しようとした場合は、現在の状態を一切変更せずに拒否しなければならない
- **FR-013**: セーブステートの復元直後に、復元前の音声が再生されてはならない

**フロントエンド / CLI**

- **FR-014**: ユーザーは `lispgb [options] <ROMファイル>` の形式で起動できなければならない
- **FR-015**: システムは次のオプションを受け付けなければならない：`-h/--help`、`-v/--version`、`--scale N`、`--fullscreen`、`--shader nearest|smooth`、`--recent`、`--headless`、`--frames N`、`--screenshot PATH`
- **FR-016**: システムは、固定のキー割り当て（矢印キー=十字キー、Z=B、X=A、Enter=Start、右Shift=Select、F1=保存、F3=復元、Esc=終了）で入力を受け付けなければならない
- **FR-017**: システムは設定ファイル（scale、fullscreen、shader、volume）を OS の慣習に従う場所から読み込み、なければ既定値で生成しなければならない（Linux は `$XDG_CONFIG_HOME/LispGB/`、未設定なら `~/.config/LispGB/`。macOS は `~/Library/Application Support/LispGB/`。Windows は `%APPDATA%\LispGB\`。macOS と Windows は将来の対象）。CLI オプションは設定ファイルより優先する
- **FR-018**: システムは、最近起動した ROM を新しい順に最大10件記録し、`--recent` で一覧表示しなければならない
- **FR-019**: ヘッドレスモードでは、ウィンドウも音声出力も使わずに指定フレーム数を実行し、指定があればフレームバッファを画像ファイルに保存してから終了しなければならない
- **FR-020**: すべてのエラーは日本語の分かりやすいメッセージで標準エラー出力に出し、0 以外の終了コードを返さなければならない

**検証 / 開発基盤**

- **FR-021**: プロジェクトは、テスト ROM（Blargg、Mooneye acceptance、acid2）をコミット固定の取得元から取ってくるスクリプトを持ち、取得した ROM はリポジトリの管理対象外にしなければならない
- **FR-022**: プロジェクトは、コア各部の単体テストとテスト ROM による結合テストを一括で実行できる手段を持たなければならない
- **FR-023**: ビルドとテストの手順はローカルと CI で同じでなければならない。手順が複雑な場合はスクリプトにまとめる
- **FR-024**: 配布物は単体の実行ファイル（と必要な付属ファイル）を収めた zip でなければならない。利用者の環境に Common Lisp の処理系やライブラリがなくても動作し、追加で必要なのはマルチメディア層の共有ライブラリだけとする。その導入手順は README に記載する

### Key Entities

- **カートリッジ**: ROM データ、ヘッダ情報（タイトル、カートリッジ種別、ROM / RAM サイズ、GBC 対応フラグ、チェックサム）、外部 RAM、バッテリー有無、MBC 状態（バンク番号、RAM 有効化、RTC レジスタ）
- **マシン状態**: CPU レジスタとフラグ、割り込み状態、WRAM / VRAM / OAM / HRAM / IO レジスタ、タイマー、画面描画状態とフレームバッファ、音声チャンネル状態、ジョイパッド状態、GBC 固有状態
- **セーブステート**: マシン状態全体のスナップショット。識別子、フォーマットバージョン、ROM 識別情報を持つ
- **設定**: 表示倍率、フルスクリーン、補間方式、音量
- **最近使った ROM 一覧**: ROM パスの順序付きリスト（最大10件）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Blargg の `cpu_instrs`（全11個）、`instr_timing`、`dmg_sound` に全部合格する
- **SC-002**: RuxBoy が使っている Mooneye acceptance テスト（timer / interrupts / ppu 等）のうち、RuxBoy が合格しているものすべてに合格する（RuxBoy の既知の不合格3件 `rapid_toggle`、`reti_timing`、`stat_lyc_onoff` は必須にしない）
- **SC-003**: dmg-acid2 と cgb-acid2 の出力フレームが、参照画像と目視で照合済みの期待値（フレームバッファのハッシュ）と一致する
- **SC-004**: 開発環境（Linux arm64）で、ウィンドウ表示・音声ありの状態で、実機と同じ速度（59.7fps）を音切れなく維持する。ヘッドレスでは実機の3倍以上の速度で動作する
- **SC-005**: ROM を指定してからゲーム画面が表示されるまで2秒以内
- **SC-006**: セーブステートの保存・復元をそれぞれ100回繰り返しても、毎回復元後の状態が保存時と完全に一致する
- **SC-007**: README に記載したキー操作と CLI オプションがすべて記載どおりに動作する

## Assumptions

- 実装言語は Common Lisp とする（ユーザー指定）。処理系、マルチメディア層、ライブラリの選定は計画フェーズで決める
- 「RuxBoy と同等」とは、RuxBoy の README と開発文書に記載された機能、CLI オプション、キー割り当て、テスト合格水準を指す。RuxBoy が「移植対象外」とした機能（ゲームパッド入力、キー割り当てのカスタマイズ、マルチスロットのセーブステート、RTC の永続化、`--recent` の対話選択、保存先の変更や表示言語の切り替え）は今回も対象外とする
- 本仕様の完成条件とする対応プラットフォームは、開発環境である Linux（arm64 / aarch64、Ubuntu 24.04 以降）とする。Linux amd64、macOS、Windows は Linux arm64 で完成した後に広げる（RuxBoy の「1 つの OS で完成させてから広げる」方針に合わせる）。FR-017 の macOS / Windows のパスは将来の展開に向けた規定とする
- 配布は GitHub Releases で、各プラットフォーム向けの zip とする（中身は FR-024 の単体の実行ファイル）。CI / CD（GitHub Actions）を用意するが、コミットとプッシュはユーザーの明示的な指示があるまで行わない
- BIOS（ブート ROM）は使わず、起動直後のレジスタ値を直接設定して開始する
- バージョン番号はセマンティックバージョニング、ライセンスは MIT（RuxBoy / BubiBoy Lite に合わせる）
- ソースコードのコメントとユーザー向けのメッセージは日本語とする
- 市販ゲーム ROM での動作確認が必要になった場合は、実行前にユーザーに相談する
- 実際のユーザー名をコード、設定、ドキュメントに残さない（パスは `~` / `$HOME` で表す）
